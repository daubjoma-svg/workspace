# ADR-003: 凭据采用 AES-256-GCM 可逆加密，主密钥走环境变量

## Status
Accepted (2026-08-04)

## Background
现状 `ai_providers.api_key`（`db.js:38`）与 `settings['gitlab.token']`（`gitlab.js:22`）**均为明文落盘**。
`sop.db` 是普通文件且开启 WAL，一次备份/拷贝/误提交即全量泄露。
注意 `gitlab.js:26` 的 `maskedCfg()` 仅做**展示层**打码，易被误认为已处理存储安全。

## Decision
采用 `node:crypto` 内置 **AES-256-GCM**。
- 存储格式 `v1:<iv_b64>:<tag_b64>:<cipher_b64>`，每条独立随机 12 字节 IV，带版本前缀便于轮换。
- 主密钥来自环境变量 `SOP_MASTER_KEY`（32 字节 base64），**不入库、不入仓、不写配置文件**。
- 缺失时启动 fail-fast 并给出指引，**不静默降级为明文**。
- 解密只在发起第三方调用前执行，不进日志、不进 API 响应。
- 启动时检测存量明文（无 `v1:` 前缀）自动加密回写一次。

**明确排除哈希方案（bcrypt/argon2/SHA）用于 API Key / Token**：这类是要拿去调用第三方的凭据，
**必须可逆解密**。哈希在此场景根本不可用——这是常见误用，写入 ADR 以防开发套用密码存储的惯例。

**凭据分流（pm 安全审计补充）**：`users.password`（`db.js:16`）是**登录口令，性质不同，必须用不可逆哈希**——
bcrypt（cost=10）。`routes.js:25` `WHERE username=? AND password=?` 明文比对，改造为先按 username 查行、
再 `bcrypt.compare(input, row.password)`。存量明文密码一次性哈希化迁移（MVP 用户少，管理员重置）。
即：**可逆凭据（api_key/token）→ AES-256-GCM；不可逆口令（password）→ bcrypt**，二者不可混用。

否决云 KMS / Vault：需外部服务与联网，一期环境不具备，过重。

## Consequences
正面：零新增依赖；数据库泄露不等于凭据泄露；版本前缀支持未来算法轮换。

负面：
- `SOP_MASTER_KEY` 丢失则存量密文不可解（缓解：文档强调备份；解密失败按"未配置"处理并提示重填，不崩溃）；
- 部署多一个必需环境变量（已纳入端到端验证步骤）。
