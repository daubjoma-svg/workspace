# ADR-009：PRD 生成与 Jira 闭环

## 状态

已采纳

## 背景

需求评审完成后，产品需要得到一份可以直接复制到飞书的 PRD，并在产品确认时快速创建 Jira。Jira 的地址和认证属于产品账号配置，需求本身只保留创建后的链接。

## 决策

1. PRD 继续作为 `artifacts(kind=PRD)` 版本化保存。AI 在需求评审后通过 `PRD_GEN` 节点生成 HTML/Markdown，产品可以在富文本编辑器中修改、预览、复制并保存新版本。
2. 每个产品账号保存一个 Jira Profile：服务地址、用户名、API Token、项目 Key、Issue Type，以及可选的 Jira 自定义字段 ID 映射。Token 使用现有密文存储能力保存，读取接口只返回是否已配置。
3. 创建 Jira 由服务端调用 Jira REST `POST /rest/api/2/issue`。概要、描述和人员来源于当前需求；客户、产品、研发、前端、参与人、报告人、QA 作为可选自定义字段写入，未配置字段映射时追加到描述的需求元数据中。
4. 创建成功后将 Jira 返回的 `self`/`key` 组合成浏览链接，回写 `requirements.jira_url`，并记录时间线，保证可重试和可审计。手动粘贴 Jira 链接仍然保留。

## 取舍

Jira 不同实例的人员字段类型和自定义字段 ID 不一致，因此不在系统中写死字段 ID。配置映射允许实例级适配；没有映射时不阻断创建，人员信息以描述元数据保留。
