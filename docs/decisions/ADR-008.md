# ADR-008: 敏感文件过滤作为 LLM 网关前置拦截层（F2 前置于 F3）

## Status
Accepted (2026-08-04)

## Background
pm 安全审计发现 BLOCKER-6：`gitlab.js:123` `CODE_EXT` 白名单含 `.properties`/`.yml`/`.yaml`/`.xml`，
`gitlab.js:124` `PRIORITY_RE` 含 `config`/`application` 关键词，`gitlab.js:155` 命中 `score += 10`。
叠加后 Spring Boot 的 `application.properties`（含 `spring.datasource.password`、Redis 密钥、JWT secret）
因浅层位置净分高于深层 Controller，排到 `keyFilesContent` 返回数组首位，随 `buildCodeContext` 注入 prompt
直发 Claude/OpenAI。F3（LLM 网关）一旦接通即瞬间泄漏生产凭证。

## Decision
**F2（敏感文件过滤）作为 F3（LLM 网关）的硬前置**，采用两层过滤，实现于 `keyFilesContent` 内部：

1. **L1 注入前剔除**：新增 `isSensitiveFile(relPath)` 纯函数，用文件名正则（非纯扩展名，因 pom.xml 等
   需保留）判定 `application[-.]?.*`、`bootstrap`、`logback`、`nacos/sentinel/seata` 配置、
   `credentials/secrets`、`.env/.key/.pem/.p12/.jks/.pfx` 等，命中即从 `scored` 数组移除，不进入 prompt。
   不影响本地磁盘留存。

2. **L2 内容嗅探脱敏**：新增 `redactSecrets(content)` 纯函数，对 L1 未剔除的文件读取后正则替换
   `password/secret/api_key/token` 赋值、AWS Access Key ID、PEM 私钥块为 `***REDACTED***`，
   保留文件结构、只抹值，不影响 AI 理解代码骨架。

两个函数纯函数化，便于正则测试集单测覆盖。

否决"配置文件语义解析提取非敏感结构"（C 方案）：成本高，二期候选。
否决"仅靠 L1 不做 L2"：存在不在文件名正则覆盖内的泄露模式（如代码内硬编码 token），需 L2 兜底。

## Consequences
正面：
- F3 接通前消除生产凭证泄漏风险，安全门在前、能力在后；
- 改动局限在 `keyFilesContent` 内部，对外接口形状 `{ path, content }[]` 不变，与 F9（打回改造）解耦、可并行；
- 正则脱敏对后续接入更多 Provider（DeepSeek/Kimi 等）同样生效，一处拦截全局受益。

负面：
- 正则有漏报风险（命名不规范的敏感文件可能逃逸），需持续补测试集；
- 脱敏后 `***REDACTED***` 会占位，极少数场景可能干扰 AI 理解配置含义（可接受，安全优先）。
