# ADR-006: 一期不做向量化，维持启发式代码上下文提取

## Status
Accepted (2026-08-04)

## Background
需求目标是"让 AI 评估/研发提示词长在真实代码上"。
现状 `gitlab.js:127-196` 已实现：目录树（限深度/条目）+ 关键文件启发式挑选
（`PRIORITY_RE` 命中 Controller/Service/Entity/Api/Handler，浅层优先）+ 字符预算截断。
任务书已明确一期不做向量化，本 ADR 记录该结论及其配套修正。

## Decision
维持**启发式提取**（方案 A），否决向量化 RAG（方案 B）与 AST 符号索引（方案 C）。
理由：SQLite 无原生向量支持，引入向量库需新增基础设施；一期模块数与代码量下，
启发式已能提供足够上下文；AST 索引留作二期候选。

但必须修正三项：
1. **修复 token 预算失效**：`ai.js:222` 传入 `{ withFiles:true, maxFiles:6 }`，
   而 `withCodeContext`（`ai.js:206`）签名只解构 `{ withFiles }`，
   转调 `buildCodeContext(mids,{withFiles})` 时 `maxFiles` **被静默丢弃**，
   实际恒用默认值 8（`gitlab.js:147`）。DevPrompt 的预算控制目前是失效的。
2. **预算动态化**：按 provider 的 `context_window` 计算，而非写死 16000 字符。
3. **命中文件回显**：新增 `GET /api/v1/requirements/{id}/code-context`，
   让使用者知道 AI 实际读了哪些文件——当前用户无从判断结论可信度，
   这对"长在真实代码上"的可信度至关重要。

另需修正数据源歧义：`ai.js:207` 读冗余列 `req.module_ids`，
而关系真值在 `requirement_modules` 表（`db.js:166`）。两者不同步会导致取错模块。
以关系表为准，冗余列由服务层统一维护或废弃。

## Consequences
正面：零新增基础设施；改造面小；预算修复后 DevPrompt 上下文可控。

负面：
- 大型仓库下启发式命中率有限，可能漏掉真正相关的文件（缓解：命中清单回显，人工可发现）；
- 无语义检索能力，跨文件关联推理弱（二期再解）。
