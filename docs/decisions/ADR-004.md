# ADR-004: 前端图标库锁定 lucide-react，全面移除 emoji 图标

## Status
Accepted (2026-08-04)

## Background
团队 P0 绝对规则：禁止 emoji 作为功能图标，必须锁定一套 SVG 图标库。
审计结果：当前项目 **46 处** emoji 用作功能图标——
`Board.tsx` 35 处（角色/节点/统计卡）、`ReqList.tsx` 9 处（状态分组）、
`CreateModal.tsx` 1 处、`server/src/gitlab.js:139` 1 处（目录树，会注入 LLM prompt）。

**关键发现**：`ReqList.tsx:50-57` 的 emoji **参与业务逻辑**，被拼进分组 key 字符串，
排序谓词用 `startsWith('✅')` 判断。直接删字符会同时破坏分组与排序——
这点若不点明，极可能被当作"替换字符"草率处理而引入回归。

## Decision
锁定 **`lucide-react@^0.454.0`**，全项目唯一图标库。

选型对比（lucide-react / @heroicons/react / @tabler/icons-react）：
- lucide：ISC 许可，~1500 图标，覆盖角色/流程/状态/代码/AI 全部语义，stroke-2 风格与现有后台一致；
- heroicons：仅 ~300 图标，流程类语义覆盖不足；
- tabler：~5800 图标但明显臃肿，细线风格与现有视觉不符。

强制条款：
1. 全项目只用这一套，禁止混用；
2. 禁止任何 emoji 作为功能图标，含服务端生成且会被展示的文本；
3. 图标统一经 `web/src/components/Icon.tsx` 收口（统一 size/stroke/color），页面不直接散引；
4. `ReqList.tsx` 分组必须重构为 `{ key, label, icon, weight }` 结构化描述，
   **不得**用字符串前缀判断，再渲染图标；
5. `gitlab.js:139` 目录树是喂给 LLM 的文本而非 UI，改为 ASCII 前缀 `[D]`/`[F]`，
   **不要**在此塞 SVG——既守规则又省 token。

完整 emoji → lucide 映射表见 `docs/tech-spec-phase1.md` §5.5。

## Consequences
正面：视觉统一；跨平台渲染一致（emoji 在不同 OS 字形差异大）；符合 P0 规则；tree-shaking 后体积可控。

负面：
- 新增一个前端依赖；
- `ReqList.tsx` 分组逻辑需结构化重构，非纯替换，工作量高于表面估计（已登记为风险 R6）。
