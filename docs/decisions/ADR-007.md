# ADR-007: API 版本化采用双挂载渐进迁移

## Status
Accepted (2026-08-04)

## Background
团队规范要求所有端点带 `/api/v1` 版本前缀。
现状全部端点挂在 `/api`（`index.js:10-11`），前端 `web/src/api.ts` 及各页面共数十处调用硬编码 `/api/...`。
全量改造会触及前端每一处调用，回归面大而收益低。

## Decision
服务端对同一 router 做**双挂载**：
```js
app.use('/api/v1', router);   // 新
app.use('/api', router);      // 存量兼容
app.use('/api/v1/admin', admin);
app.use('/api/admin', admin);
```
- 文档与新增端点一律以 `/api/v1` 为准；
- 前端新代码用 `/api/v1`，存量调用保持可用，逐步迁移；
- 存量端点保持**裸 JSON** 响应；**仅新增端点**使用 `{code,data,message}` 包络。
  这条要在 Spec 写死——否则前端会对响应形状产生混淆。

## Consequences
正面：零破坏、零额外成本即满足版本化规范；迁移可按页面节奏推进。

负面：
- 过渡期同一资源有两个可用路径，需靠文档纪律约束新代码只用 v1；
- 响应形状短期不统一（裸 JSON 与包络并存），已在 openapi.yaml 顶部显式说明。
