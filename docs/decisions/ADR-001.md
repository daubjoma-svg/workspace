# ADR-001: LLM 统一抽象层采用自研轻量 Adapter

## Status
Accepted (2026-08-04)

## Background
一期需接入真实 LLM 网关，支持 Anthropic Claude Messages API 与 OpenAI 兼容协议（Kimi/DeepSeek/GLM 等），并保留失败降级 Mock。
现状 `server/src/ai.js:20-61` 已有双协议分支雏形，但无抽象层、无能力矩阵、无超时、无可观测。
需决定：继续自研，还是引入现成 SDK / 代理网关。

## Decision
采用**自研轻量 Adapter**，落地为 `server/src/llm/` 包（index/capabilities/providers/structured）。

否决 Vercel AI SDK / LangChain.js：后端为 CommonJS（`server/package.json` `"type":"commonjs"`），
而这类 SDK 主线为 ESM-only，引入需改造整个后端模块规范，代价远超收益；且其依赖树相对当前
「仅 2 个生产依赖」的极简后端过重。

否决自建 OneAPI / LiteLLM 代理：多一个进程/容器要部署与运维，MVP 阶段不划算。
但保留兼容路径——Adapter 的 `base_url` 可配置，未来切换到代理网关只需改配置，不改代码。

## Consequences
正面：
- 零新增运行时依赖，与现有 CJS 后端无缝；
- 一期只需两种协议，抽象层规模可控（< 200 行）；
- 完全掌控超时、重试、降级、埋点等关键行为。

负面：
- 新增 Provider 需自行适配（可接受，一期范围内 Provider 有限）；
- 不能白嫖 SDK 的流式/工具调用等能力（一期无此场景，见 tech-spec §7）。
